# 主的旨意 — 設計文件

日期：2026-08-29

## 一、這是什麼

一個純靜態的諷刺網站。使用者打進一個人生煩惱，網站用**一字不改的和合本經文**回答，下面附一句假牧師的「屬靈解讀」補刀。

形式上像《解答之書》，但每個答案都引經據典、可回查原文。

**諷刺的對象是「斷章取義」這件事本身**，不是信徒個人。笑點的來源是：經文一旦被當成萬用金句拿來套用，它會自己說出很荒謬的話。因此全站唯一的規則是經文絕對不改字 —— 一改就沒有笑點了，因為笑點正是「這真的是聖經寫的」。

範例：

> 你問：我老婆不好
>
> 「你們作妻子的、當順服自己的丈夫、如同順服主．」 —— 以弗所書 5:22
>
> 弟兄，問題不在她好不好，而在你還沒帶她上主日學。

## 二、範圍

**做**：單頁問答、策展主題庫、隨機兜底、答案卡產圖、網址分享。

**不做**（YAGNI）：帳號系統、任何後端、熱門提問牆、多語言、留言區、經文全文檢索介面。

## 三、資料來源

`bible-cut/CUT/` 已有完整和合本（繁體）語料：70 個內容檔（66 卷，詩篇拆成 Book1–5），每節都有 `<p id="Eph5v22">` 形式的錨點。已驗證可乾淨抽出 **31,031 節**。

抽取正規表示式（已驗證）：

```python
re.finditer(r'<p id="([A-Za-z0-9]+?)(\d+)v(\d+)"[^>]*>(.*?)</p>', html, re.S)
```

`[^>]*` 不可省略：耶穌的話在原檔中帶 `class="wj"`（紅字經文），寫成 `<p id="Matt19v24" class="wj">`。少了它會靜默漏掉 114 節，其中包含「駱駝穿過鍼的眼」這類關鍵素材。

抽出後去除內層標籤、`html.unescape`、去掉開頭重複的節號數字。詩篇需注意檔名分為 `CUT_Psalms-Book1..5`，但章號是全書連續的。

## 四、架構

純靜態單頁，零後端、零建置工具，可直接部署 GitHub Pages。

### 資料流

```
使用者輸入
  → 正規化（去標點空白、全形轉半形）
  → 掃 topics.json，每個主題算命中分數
  → 最高分 ≥ 門檻？
      是 → 從該主題經文池抽一節（seed = hash(問題)）
      否 → 從 fallback.json 隨機抽一節，套用「兜底包裝詞」
  → 渲染答案卡
```

### 比對演算法

三層，由精準到寬鬆。中文不需要斷詞。

**第一層：加權關鍵字（精準）**

每個主題手寫一組關鍵字，直接用 `String.includes` 掃描輸入字串。

- 每個關鍵字有權重：核心詞 3 分（「老婆」），邊緣詞 1 分（「吵架」）
- 主題分數 = 命中關鍵字權重總和
- 取最高分主題；門檻為 3 分（至少命中一個核心詞，或三個邊緣詞）
- 同分時取關鍵字表較長者（較具體的主題優先）

**第二層：字元 bigram 的 TF-IDF 餘弦相似度（寬鬆）**

第一層落空時才啟用。每個主題除了關鍵字，另外手寫一組 `phrases`（幾句台灣人實際會怎麼講這件事的自然例句）。

- 特徵：**只用字元 bigram，不用 unigram**。實測 unigram 會讓「我、的、很、每、天」這類高頻字造成假相似 —— 「主管每天罵我」會因為和「每天都想死」共用字元而被判成憂鬱主題
- 每個主題的文件 = 它所有 `phrases` 串接；離線不預算，載入時即時建索引（30 個主題的規模，成本可忽略）
- TF-IDF 加權後做 L2 正規化，取餘弦相似度最高的主題
- 餘弦門檻 0.05。實測在 0.02–0.10 之間對負面案例都無誤判，取中間值；主題數增加後需要重新校準

**第三層：兜底隨機**

前兩層都落空，從 3,800 節的兜底池隨機抽。

**為什麼是混合而不是純向量：** 實測 17 條真實問法，純關鍵字表 8 條正確，純向量單獨使用反而更差（門檻切不乾淨，正確命中 0.065 卻低於錯誤命中 0.102），混合則 17 條全對。關鍵字表是手調過的精準訊號，不該被丟掉；向量的價值在於接住「差一點」的問法，讓它們不要掉進隨機池。

**這一層做得到與做不到的事：** 字元 bigram 沒有語意概念。「內人很難相處」能被接住，是因為 `phrases` 裡寫了這句或相近的句子，不是因為模型知道「內人」等於「妻子」。所以同義詞的涵蓋仍然來自手寫的 `phrases`，向量的作用是讓每一句例句覆蓋它周圍的一小片鄰域，而不是只認完全相同的子字串。

「再求一次」在同一主題內輪替下一節，並**同步把 `&n=<索引>` 寫進網址**（`history.replaceState`），確保使用者看到什麼、複製出去的連結就是什麼。索引超出經文池長度時取模回繞。

### 決定論與分享

答案必須可重現：`?q=我老婆不好` 分享出去，別人點開要看到**同一張卡**。

作法：以問題字串的 FNV-1a hash 當亂數種子選經文，`n` 參數（預設 0）作為在該主題經文池中的位移。同一組 `(q, n)` 永遠得到同一節。

## 五、內容設計

這是整個專案的真正工作量與全部價值所在。

### 規模

v1 目標：**30 個主題，平均每主題 6 節經文，約 180 條手寫內容。**

### 主題分類

| 群組 | 主題 |
|---|---|
| 婚姻伴侶 | 老婆不好、老公廢、想離婚、外遇、婆媳 |
| 女性處境 | 職場被壓、想發言、生育壓力、生理期 |
| 性與慾望 | 單身、約砲、自慰、同性戀、看A片 |
| 工作 | 老闆爛、想離職、加班、薪水低、同事機車 |
| 金錢 | 負債、想發財、投資、買房 |
| 人際 | 被霸凌、朋友背叛、想報復 |
| 存在 | 憂鬱、失眠、生病、怕死、人生沒意義 |
| 彩蛋 | 「神存在嗎」、「你是在嘲笑基督徒嗎」、「這網站誰做的」 |

### 資料格式

`data/topics.json`：

```json
{
  "topics": [
    {
      "id": "wife-complaint",
      "label": "抱怨老婆",
      "keywords": [
        { "w": "老婆", "s": 3 }, { "w": "妻子", "s": 3 },
        { "w": "太太", "s": 3 }, { "w": "牽手", "s": 1 },
        { "w": "黃臉婆", "s": 3 }, { "w": "另一半", "s": 1 }
      ],
      "phrases": [
        "我老婆很煩", "太太一直唸我", "跟妻子吵架",
        "另一半很難搞", "內人很難相處", "老婆脾氣很差"
      ],
      "verses": [
        {
          "ref": "以弗所書 5:22",
          "id": "Eph5v22",
          "text": "你們作妻子的、當順服自己的丈夫、如同順服主．",
          "quip": "弟兄，問題不在她好不好，而在你還沒帶她上主日學。"
        }
      ]
    }
  ]
}
```

`id` 欄位對應 CUT 原檔的錨點，供驗證腳本比對用，也可以拿來做「查看原文」連結。

`keywords` 供第一層精準比對，`phrases` 供第二層向量比對。兩者都要寫：關鍵字負責「一定要中」的核心詞，例句負責涵蓋自然的講法。

### 補刀的寫作規範

補刀是全站唯一的原創文字，笑點成敗在此。

1. **一到兩句**，教會長輩的溫柔口吻
2. **立場永遠是「經文顯然是對的，是你不夠屬靈」** —— 補刀的功能是把問題弄得更糟，不是評論經文
3. **絕不破梗**：不出現「哈哈」、「其實」、「這是諷刺」、顏文字，或任何自我揭露
4. **不攻擊具體的人或教會**，攻擊的是這套推論方式

### 兜底包裝詞

沒命中主題時，隨機經文外面套一句框：「神的意念高過你的意念。」「你所求的，不一定是你所需的。」「主已經回答了，是你還沒讀懂。」共約 8 句輪替。

`data/fallback.json` 不放全部 31,031 節 —— 一來拖慢載入，二來絕大多數經文（族譜、獻祭條例、敘事片段）根本不像在回答問題。

過濾規則（已實測）：

1. **書卷白名單**：詩篇、箴言、傳道書、雅歌、四福音、保羅書信、希伯來書、雅各書、彼得前後書、約翰一書、猶大書。律法書與歷史書整卷排除 —— 這些書裡真正好笑的經文（利未記的月經與同性條例等）改由 `topics.json` 精選收錄，不進兜底池
2. **長度**：去標點後 12–45 字
3. **敘事特徵排除**：含「生了」「的兒子」「後裔」「說、」「於是」「支派」「祭」「燔」等
4. **箴言語氣要求**：必須含「你 / 當 / 不可 / 凡 / 務要 / 要 / 人若 / 惟有 / 豈」之一

實測結果：**3,800 節，JSON 約 539KB**（含 `ref` 與 `id` 欄位）。抽樣檢查命中率約七成「讀起來像在回答你」，其餘的荒謬感由兜底包裝詞吸收，可接受。若日後要提高品質，做法是人工掃一遍 3,800 節刪掉明顯的啞彈，而不是再加規則。

## 六、視覺

莊嚴聖經風。外表越像真的，反差越大。

- 米白紙底（`#f4f0e6` 一類）、暗金分隔線（`#8a7434`）
- 中文襯線體（`Noto Serif TC`，fallback 到系統 `PMingLiU` / `Songti TC`）
- 章節號、經文排版比照真實聖經頁面
- 安靜、無動畫、無鮮豔色彩

## 七、分享

### 網址

`?q=<問題>`，載入時自動作答；按過「再求一次」則網址會多一個 `&n=<索引>`。分享者與接收者永遠看到同一張卡（見「決定論與分享」）。

### 產圖

840×1200 直式卡，一鍵存 PNG。

**用 canvas 手繪，不用 html2canvas** —— html2canvas 處理中文字型經常出錯（缺字、行高跑掉），自己畫反而穩定可控。`card.js` 負責：載入字型 → 畫背景與金線 → 逐行排版經文（手動換行計算）→ 畫出處與補刀 → `toBlob` 下載。

## 八、錯誤處理

| 情況 | 處理 |
|---|---|
| 空輸入 | 顯示「你的問題呢？『你們祈求、就給你們』」 |
| 輸入超過 100 字 | 一律截斷至 100 字（輸入框 `maxlength` 與網址 `q` 參數皆是），比對用截斷後的字串 |
| `topics.json` 載入失敗 | 退到 `app.js` 內建的 20 節硬編碼池，網站仍可用 |
| `fallback.json` 載入失敗 | 同上 |
| 產圖失敗（字型未載入等） | 按鈕改為「複製文字」，並顯示提示 |
| 網址 `q` 參數過長或含控制字元 | 忽略參數，正常顯示首頁 |

## 九、測試

| 測試 | 內容 |
|---|---|
| `tests/match.test.js` | 30 條 `問題 → 預期主題 id` 的 fixture，涵蓋每個主題至少一條，加 5 條應走兜底的冷門問題 |
| `tools/verify.py` | **關鍵**：逐條比對 `topics.json` 每節經文與 `CUT/` 原檔是否一字不差。這支腳本保護整站的立身之本，任何不符即失敗 |
| 兜底池檢查 | `fallback.json` 無空字串、每節長度在 15–60 字內、無重複 ref |
| 決定論檢查 | 同一組 `(q, n)` 連續呼叫 100 次回傳同一節；不同 `n` 回傳不同節 |

## 十、檔案結構

```
bible-oracle/
  index.html
  assets/
    style.css
    app.js          # 主流程、DOM 綁定
    match.js        # 比對邏輯（純函式，可單獨測）
    card.js         # canvas 產圖
  data/
    topics.json     # 策展庫（手寫，核心資產）
    fallback.json   # 兜底經文池（腳本產生）
  tools/
    extract.py      # 從 bible-cut/CUT 抽經文 → fallback.json
    verify.py       # 驗證 topics.json 與原檔一字不差
  tests/
    match.test.js
```

`match.js` 與 `card.js` 拆開，是為了讓比對邏輯能在沒有瀏覽器的情況下測試，也讓每個檔案小到容易修改。`app.js` 只做接線，不含業務邏輯。

## 十一、實作順序建議

1. `tools/extract.py` → 產出 `fallback.json`，確認資料管線通
2. `match.js` + `tests/match.test.js` → 比對邏輯先綠
3. 寫 5 個主題的 `topics.json` → 跑 `verify.py` 確認格式與原文比對可用
4. `index.html` + `style.css` + `app.js` → 端到端能問能答
5. 補滿 30 個主題（最花時間，但可以隨時停下來就有可用的網站）
6. `card.js` 產圖 + `?q=` 分享
